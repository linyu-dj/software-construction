# Task02 · V1.1 用户注册功能

## 本任务目标

解决 V1.0 账号硬编码、无法新增用户的问题：主菜单增加注册入口，账号数据改由 `HashMap` 管理，并把校验逻辑从主流程里抽出来。

## 目录结构

```
Task02-V1.1-用户注册功能/
├─ src/
│  └─ campus/
│     └─ SystemMain.java     主类：菜单调度 + 登录流程 + 注册流程 + 两个校验方法
└─ run.bat                   命令行一键编译 + 运行
```

## 本版本改了什么

| 项 | V1.0 | V1.1 |
|---|---|---|
| 菜单 | `1` 登录 / `0` 退出 | `1` 登录 / `2` 注册 / `0` 退出 |
| 账号存储 | 四个局部变量写死在 `main` 里 | `HashMap<String, String>`，用户名 → 密码 |
| 新增用户 | 必须改代码重新编译 | 控制台注册即可 |
| 校验 | 判断散落在主流程 | 抽成 `validateUsername` / `validatePassword` 两个方法 |
| 注册校验 | 无 | 用户名非空 + 查重；密码非空 + 长度 ≥ 6 |

## 预置账号

程序启动时向 `HashMap` 里放两个演示账号（不再是写死在判断里的常量）：

| 角色 | 账号 | 密码 |
|---|---|---|
| 管理员 ADMIN | `admin` | `123456` |
| 学生 STUDENT | `student` | `123456` |

注册的新账号与学生走同一套流程，因此角色按 STUDENT 处理。

## 验收用例

| 用例 | 输入 | 预期输出 |
|---|---|---|
| 注册新账号 | `2` → `zhangsan` → `123456` | 注册成功，账号 zhangsan 已创建 |
| 注册后可登录 | `1` → `zhangsan` → `123456` | 登录成功，身份 STUDENT |
| 用户名查重 | `2` → `student` → `654321` | 注册失败：账号 student 已存在 |
| 密码长度不足 | `2` → `lisi` → `abc12` | 注册失败：密码长度不能少于 6 位 |
| 账号为空 | `2` → 回车 → `123456` | 注册失败：账号不能为空 |
| 登录未注册账号 | `1` → `wangwu` → `123456` | 登录失败：该账号尚未注册 |
| 密码错误 | `1` → `admin` → `111111` | 登录失败：密码错误 |
| 无效选项 | `3` | 无效选项，请输入 0、1 或 2 |

## 设计原则落地

**单一职责原则**：`validateUsername`、`validatePassword` 只负责判断，返回错误描述或 `null`，不打印、不修改状态；`doLogin`、`doRegister` 只负责取输入、调校验、给结果；`main` 只负责循环与菜单调度。

## 已知局限（后续版本接手）

- 账号密码只存在内存里，程序退出即丢失 → V1.3 用文件持久化解决
- 角色靠"用户名是不是 admin"推断，没有真实字段 → V1.2 引入 `User` 实体解决
- 错误用字符串提示，无法区分业务错误类型 → V1.4 用自定义异常解决
