# Task04 · V1.3 IO 文件持久化

## 本任务目标

解决前两版"程序一退出用户就没了"的问题：新增 `FileUtil` 工具类把用户数据写入 `user.txt`，启动时自动加载，注册成功后立即落盘。

## 目录结构

```
Task04-V1.3-IO文件持久化/
├─ src/
│  └─ campus/
│     ├─ SystemMain.java        主类：启动加载、登录、注册、校验
│     ├─ entity/
│     │  └─ User.java           实体类（与 V1.2 一致）
│     └─ utils/
│        └─ FileUtil.java       文件操作：创建、加载、覆盖写入、追加写入
├─ user.txt                     运行时自动生成，已被 .gitignore 忽略
└─ run.bat
```

## 数据文件格式

一行一个用户，字段用竖线分隔：

```
username|password|role|registerTime
admin|123456|admin|2026-11-13 00:00:00
student|123456|student|2026-11-13 00:00:00
```

## 本版本改了什么

| 项 | V1.2 | V1.3 |
|---|---|---|
| 数据存活范围 | 仅当前进程内存 | 写入 `user.txt`，跨进程保留 |
| 读取 | 无 | 启动时 `FileUtil.loadUsers()` 加载 |
| 写入 | 无 | 注册后 `FileUtil.appendUser()` 立即追加 |
| 首次运行 | 预置账号只存在内存 | 文件不存在则自动创建并写入预置账号 |
| 用户名限制 | 只查空值和重复 | 额外禁止包含 `|`，避免破坏行格式 |

## 运行方式

```powershell
cd "Task04-V1.3-IO文件持久化"
.\run.bat
```

注意 `user.txt` 生成在**程序运行目录**。用 `run.bat` 时脚本会先 `cd` 到本任务目录，所以文件就落在任务文件夹里；如果从别处用 `java -cp` 启动，文件会出现在那个目录。

## 验收用例

| 用例 | 操作 | 预期输出 |
|---|---|---|
| 首次启动建文件 | 删除 `user.txt` 后运行，输入 `0` | 提示"已自动创建 user.txt"，文件内有两条预置账号 |
| 注册落盘 | 输入 `2` → `zhangsan` → `123456` | 提示"已创建并保存到 user.txt"，文件多出一行 |
| 重启加载 | 关闭程序，重新运行 | 提示"已从 user.txt 加载 3 个用户" |
| 重启后登录 | 输入 `1` → `zhangsan` → `123456` | 登录成功，注册时间与注册时一致 |
| 重启后查重 | 输入 `2` → `zhangsan` → `654321` | 注册失败：账号 zhangsan 已存在 |

## 设计原则落地

**迪米特法则（Law of Demeter）**：业务代码不直接接触 `FileInputStream`、`BufferedWriter` 这些 IO 对象，只调用 `FileUtil` 的四个方法。后续如果要换成数据库或多文件存储，只需要改 `FileUtil`，`SystemMain` 一行都不用动。

## 已知局限（后续版本接手）

- 文件读写失败时只是打印一行中文提示，不区分错误类型 → V1.4 用自定义异常统一
- 用户数据全量进内存，用户量大时内存占用无上限；本课程规模可接受
- 密码明文写入文件，真实系统需加密存储（课程范围外）
