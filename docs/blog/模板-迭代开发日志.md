## 一、本轮要解决什么问题

写清楚**上一版的痛点**，不要写"本次实现了注册功能"这种结论，要写"为什么非改不可"。

例：V1.0 的账号写死在 `if ("admin".equals(u))` 里，想加一个同学就得改代码重新编译，而且账号密码存在主方法里的两个字符串变量，根本没法扩展。

## 二、改动清单

| 类型 | 文件 / 类 | 说明 |
|---|---|---|
| 新增 | `User.java` | 实体类，承载账号、密码、角色、注册时间 |
| 修改 | `SystemMain.java` | 主流程由 `HashMap` 改为 `List<User>` |
| 删除 | 硬编码账号常量 | 全部换成动态注册 |

## 三、关键设计与实现

挑 1～2 个最能体现"设计思考"的点，贴核心代码 + 逐行解释为什么这么写。

```java
// 用 List<User> 而不是 HashMap<String,String> 的原因：
// HashMap 只能存"账号→密码"两个字段，加角色就得再开一个 Map，两张表还要自己保证同步
private static final List<User> userList = new ArrayList<>();
```

## 四、踩过的坑（最重要，别省略）

老师看博客主要看这一段——证明代码是你自己写的。

| 现象 | 原因 | 解决 |
|---|---|---|
| 注册的同名账号还能登录进去 | 查重时用了 `==` 比较字符串 | 改成 `equals()`，并说明 `==` 比的是引用 |
| 重启程序用户全没了 | 数据只在内存 | 本任务先记录问题，V1.3 用 IO 持久化解决 |
