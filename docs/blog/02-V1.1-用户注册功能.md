# V1.1 用户注册：从硬编码到集合管理

> 软件构造综合实践 · 第 2 轮迭代
> 标签 `v1.1` · 2026-11-13

V1.0 的账号是四个局部变量，想加一个人就得改代码重新编译。这轮把账号挪进 `HashMap`，并补上注册入口，让"系统里有哪些用户"变成运行期可变化的数据。

## 一、这轮要动的地方

任务书列了五条：菜单增加注册、输入用户名密码、非空与密码长度校验、用户名查重、删除硬编码账号、抽离校验方法。真正需要设计判断的是后两条——怎么删、怎么抽。

硬编码好删。原来是在 `main` 里写四个变量，然后在 if-else 里逐个比较；现在改成启动时往 `HashMap` 里放两个演示账号，判断逻辑只认集合：

```java
private static final Map<String, String> USERS = new HashMap<>();
```

登录时不再关心系统里有几个账号，只做 `USERS.get(username)` 这一次查询。加人不用改代码，注册一条就进了集合。这一步改变的是数据的"来处"，不是把变量换成集合那么简单。

## 二、校验方法怎么抽

任务书要求"抽离独立校验方法：账号校验、密码合法性校验"。最直接的做法是两个方法各写一遍，但登录和注册的校验要求并不一样：

- 注册：账号必须非空**且**未被占用；密码必须非空**且**长度 ≥ 6
- 登录：账号只需非空；密码只需非空（长度是注册时的门槛，登录不该再拦）

如果写死两套，就会出现四个几乎相同的方法。我用一个布尔参数区分场景：

```java
private static String validateUsername(String username, boolean checkUnique)
private static String validatePassword(String password, boolean checkStrength)
```

`checkUnique` 在注册时传 `true`、登录时传 `false`；`checkStrength` 同理。两个方法、四种组合，代码量少一半。

返回值也有取舍：**返回错误描述字符串，通过时返回 `null`**，而不是返回 `boolean` 再让调用方自己拼提示语。这样"密码长度不能少于 6 位"这种文案只在一个地方维护，也避免了每个调用点复制同一句话。代价是调用方每次要判断 `!= null`，多一行代码，但比文案散落各处好维护。

顺带说明一下：这里没有用异常来表达校验失败。异常要等到 V1.4 引入 `BusinessException` 才有，本阶段仍然用返回值，两类错误（业务失败、程序故障）还混在一起——这正是下一轮以后要处理的事。

## 三、注册流程

```java
String usernameError = validateUsername(username, true);
if (usernameError != null) {
    System.out.println("注册失败：" + usernameError);
    return;
}
String passwordError = validatePassword(password, true);
if (passwordError != null) {
    System.out.println("注册失败：" + passwordError);
    return;
}
USERS.put(username, password);
```

注册成功后不自动登录，只提示"请使用该账号登录"。这符合真实系统的习惯：注册和登录是两个动作，自动登录会让"注册成功"这个结果难以单独验证。

## 四、一处还不干净的地方

登录成功后要判断身份，但 V1.1 的集合里只存了"用户名 → 密码"，没有角色字段。我暂时用用户名判断：

```java
String role = "admin".equals(username) ? "ADMIN" : "STUDENT";
```

这行代码很脆弱：只要有人注册一个叫 `admin` 的账号（虽然会被查重挡住），或者以后要加第三种角色，这里就必须改。本轮先这么处理，V1.2 把角色做成 `User` 的字段之后，这个判断就该删掉。

## 五、踩到的两个坑

**1. `javac: 找不到目录: out`**

V1.0 踩过一次，这轮在新目录里又碰上了：`out` 目录不存在时 `javac -d out` 直接失败。`run.bat` 里第一句已经写了 `if not exist out mkdir out`，但用脚本直接调 `javac` 测试时忘了建目录，编译退出码 2。这条属于环境问题不是代码问题，但每次新建任务目录都会重演一次。

**2. PowerShell 把 `-Dfile.encoding=UTF-8` 拆成了两半**

手动在 PowerShell 里敲：

```powershell
java -Dfile.encoding=UTF-8 -cp out campus.SystemMain
```

报的是 `找不到或无法加载主类 .encoding=UTF-8`。原因是 PowerShell 会把 `-D` 后面的点号当参数分隔处理。加引号就好：

```powershell
java "-Dfile.encoding=UTF-8" -cp out campus.SystemMain
```

`run.bat` 里不受影响，因为批处理不做这层解析。

## 六、验收

七组用例，实际输出：

| 输入 | 结果 |
|---|---|
| `2` → `zhangsan` → `123456`，再 `1` 登录 | 注册成功；登录成功，身份 STUDENT |
| `2` → `student` → `654321` | 注册失败：账号 student 已存在，请更换 |
| `2` → `lisi` → `abc12`（5 位） | 注册失败：密码长度不能少于 6 位 |
| `2` → 空账号 → `123456` | 注册失败：账号不能为空 |
| `1` → `wangwu` → `123456` | 登录失败：该账号尚未注册 |
| `1` → `admin` → `111111` | 登录失败：密码错误，请重新输入 |
| `3` | 无效选项，请输入 0、1 或 2 |

退出码均为 0。失败后都回到主菜单，没有退出程序。

## 七、下一轮

V1.2 要把"用户名 → 密码"这种扁平结构换成 `List<User>`，每个用户是一个对象，带角色和注册时间。这会连带解决上面第四节那行脆弱的身份判断。
