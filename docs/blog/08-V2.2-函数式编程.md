# V2.2 Stream + Optional：删掉 for 循环

> 软件构造综合实践 · 第 8 轮迭代
> 标签 `v2.2` · 2026-11-13

这一轮改的全是查询。功能一行没加，代码形状变了。

上一版查「可预约资源」是这样写的：

```java
List<CampusResource> result = new ArrayList<>();
for (CampusResource resource : store.findAllSortedById()) {
    if (resource.getStatus() == ResourceStatus.AVAILABLE) {
        result.add(resource);
    }
}
```

五行，中间还有一个临时集合。业务规则其实只有一句「状态是可预约的」，其余四行都在处理"怎么循环"。

## 一、改完之后的样子

```java
List<CampusResource> resources = isAdmin(operator)
        ? store.findAllSortedById()
        : store.findByStatus(ResourceStatus.AVAILABLE);
```

筛选逻辑挪进了 `ResourceStore`：

```java
return resources.stream()
        .filter(resource -> resource.getStatus() == status)
        .sorted(Comparator.comparing(CampusResource::getId))
        .collect(Collectors.toList());
```

三行，读起来是「筛状态、按编号排、收集成列表」三件事，正好对应业务里说的三件事。

任务书里点的几个查询都改成了这个形状：筛选可预约、名称模糊匹配、按 ID 升序。最后那个是 `sorted(Comparator.comparing(CampusResource::getId))`，比 `copy.sort((a, b) -> a.getId().compareTo(b.getId()))` 少一个匿名函数。

## 二、Optional 解决的问题和 for 循环无关

上一版按编号查：

```java
public CampusResource findById(String id) {
    for (CampusResource resource : resources) {
        if (resource.getId().equals(id)) {
            return resource;
        }
    }
    return null;
}
```

很多人以为这一轮要改的是「把 for 换成 stream」，其实换成

```java
return resources.stream().filter(...).findFirst().orElse(null);
```

并没有变好，还是返回 null。真正要改的是返回值类型：

```java
public Optional<CampusResource> findById(String id) {
    return resources.stream()
            .filter(resource -> resource.getId().equals(id))
            .findFirst();
}
```

`Optional` 把「可能找不到」写进类型，调用方不处理就编译不过（严格说是不处理就拿不到值）。业务层的用法：

```java
CampusResource resource = store.findById(id.trim())
        .orElseThrow(() -> new ResourceNotFoundException("未找到编号为 " + id + " 的资源。"));
```

这一行把「找不到」转成一句中文提示，再被外层 catch 转成 `Result.fail`。整条链上没有 null 对象被直接取属性。

## 三、编号生成也用上了 Optional

```java
int max = resources.stream()
        .mapToInt(resource -> parseSequence(resource.getId()))
        .max()
        .orElse(0);
```

`max()` 返回 `OptionalInt`。空集合时没有最大值，`orElse(0)` 说明「没有资源就从 0 开始编号」。空集合这件事以前是靠 `if (resources.isEmpty())` 或者初始值 `int max = 0` 兜住的，现在由返回类型提醒你处理。

这是 Optional 另一个容易被忽略的用处：它不只防空指针，还逼你把「没有」这种情况想清楚。

## 四、新增了名称模糊查询

任务书要求补一个按名称搜索，两个菜单都加了入口：

```
管理员：[1]新增 [2]查询全部 [3]按名称查询 [4]修改 [5]删除 [0]退出
学生  ：[1]查询可预约 [2]按名称查询 [0]退出
```

实现里有个小处理：

```java
private static String normalizeKeyword(String keyword) {
    return keyword == null ? "" : keyword.trim().toLowerCase(Locale.ROOT);
}
```

三个动作：null 当空串、去掉首尾空格、转小写。前两个是为了「留空即全部」，第三个是为了忽略大小写。

用 `Locale.ROOT` 不用无参 `toLowerCase()`：后者跟着系统默认区域走，土耳其语环境下 `I` 会变成 `ı`，`indexOf` 就匹配不上了。中文项目里碰不到，但写死了更省心。

## 五、多条件查询就是多一行 filter

```java
return resources.stream()
        .filter(resource -> status == null || resource.getStatus() == status)
        .filter(resource -> normalized.isEmpty()
                || resource.getName().toLowerCase(Locale.ROOT).contains(normalized))
        .sorted(Comparator.comparing(CampusResource::getId))
        .collect(Collectors.toList());
```

两个条件各占一行，空值表示「不限」。如果换成 for 循环，得写成嵌套两层 `if`，读的时候还得记住每层在筛什么。

学生查「实验」得到 0 条，是因为 R002 已经被改成占用状态——学生视图里先过滤掉了它，再匹配名称。这个顺序是刻意的：先按权限过滤，再按关键词过滤，不会出现「搜到了但你没权限看」的中间状态。


## 七、旧代码没删

每个方法上方都留了旧的 for 循环，用注释包着。不是为了留念，是任务书要求保留对比，而且讲代码的时候能直接指着说「以前五行，现在三行，省掉的是 `new ArrayList` 和 `add`」。
