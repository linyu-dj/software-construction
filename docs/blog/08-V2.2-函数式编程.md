# V2.2 查询层重构：Stream 与 Optional 的应用边界

> 软件构造综合实践 · 第 8 轮迭代
> 标签 `v2.2` · 2026-11-13

本轮不新增业务功能，改造对象是查询代码。重构的验收标准是"外部行为完全一致"，只允许内部结构变化。

改造前的"查询可预约资源"实现：

```java
List<CampusResource> result = new ArrayList<>();
for (CampusResource resource : store.findAllSortedById()) {
    if (resource.getStatus() == ResourceStatus.AVAILABLE) {
        result.add(resource);
    }
}
```

五行代码中，业务规则只有一句"状态为可预约"，其余四行都在描述"如何循环"。临时集合的创建与逐条添加属于过程性细节，与被表达的规则无关。

## 一、改造后的形式

```java
List<CampusResource> resources = isAdmin(operator)
        ? store.findAllSortedById()
        : store.findByStatus(ResourceStatus.AVAILABLE);
```

筛选逻辑下沉到 `ResourceStore`：

```java
return resources.stream()
        .filter(resource -> resource.getStatus() == status)
        .sorted(Comparator.comparing(CampusResource::getId))
        .collect(Collectors.toList());
```

三行分别对应"按状态筛选、按编号排序、收集为列表"，与被表达的规则一一对应。任务书指定的查询全部改为该形式，包括按编号排序，其中 `Comparator.comparing(CampusResource::getId)` 替代了原先的匿名比较函数。

## 二、Optional 与循环写法无关

原按编号查询：

```java
public CampusResource findById(String id) {
    for (CampusResource resource : resources) {
        if (resource.getId().equals(id)) {
            return resource;
        }
    }
    return null;
}
```

若仅把循环改成 Stream，写成 `findFirst().orElse(null)`，返回值仍是 `null`，调用方仍可能漏判。本轮真正改变的是返回类型：

```java
public Optional<CampusResource> findById(String id) {
    return resources.stream()
            .filter(resource -> resource.getId().equals(id))
            .findFirst();
}
```

`Optional` 把"可能不存在"写入方法签名，调用方无法在类型层面忽略这一点。业务层的使用方式：

```java
CampusResource resource = store.findById(id.trim())
        .orElseThrow(() -> new ResourceNotFoundException("未找到编号为 " + id + " 的资源。"));
```

这一行将"不存在"转换为中文提示，再由外层 `catch` 转为 `Result.fail`。整条链上不存在被直接取属性的 `null` 引用。这是《软件构造》中"消除空指针约定"的具体做法：不用文档约定"可能返回 null"，用类型表达。

## 三、空集合的处理

```java
int max = resources.stream()
        .mapToInt(resource -> parseSequence(resource.getId()))
        .max()
        .orElse(0);
```

`max()` 返回 `OptionalInt`。空集合没有最大值，`orElse(0)` 明确"无资源时从 0 开始编号"。此前空集合依靠 `if (resources.isEmpty())` 或初值 `int max = 0` 兜住，现在由返回类型强制处理。

这也是 `Optional` 常被忽略的作用：除了避免空指针，还强制调用方考虑"没有值"这一分支。

## 四、新增名称模糊查询

任务书要求补充按名称搜索，两类菜单都增加入口：

```
管理员：[1]新增 [2]查询全部 [3]按名称查询 [4]修改 [5]删除 [0]退出
学生  ：[1]查询可预约 [2]按名称查询 [0]退出
```

关键词统一处理：

```java
private static String normalizeKeyword(String keyword) {
    return keyword == null ? "" : keyword.trim().toLowerCase(Locale.ROOT);
}
```

三个动作：`null` 视为空串、去除首尾空格、转小写。前两个保证"留空即查全部"，第三个实现大小写不敏感。

使用 `Locale.ROOT` 而非无参 `toLowerCase()`：后者依赖系统默认区域，土耳其语区域下 `I` 会转为 `ı`，`contains` 随即失配。中文环境不会触发，但显式指定区域可以消除环境依赖，属于防御式编程中的"消除隐式环境假设"。

## 五、组合查询与条件语义

```java
return resources.stream()
        .filter(resource -> status == null || resource.getStatus() == status)
        .filter(resource -> normalized.isEmpty()
                || resource.getName().toLowerCase(Locale.ROOT).contains(normalized))
        .sorted(Comparator.comparing(CampusResource::getId))
        .collect(Collectors.toList());
```

两个条件各占一行，`null` 与空串分别表示"不限"。若改回循环，需要两层嵌套 `if`，阅读时必须逐层记住当前筛选条件。用 `filter` 串联后，每个条件独立可读，新增条件只需追加一行，符合开闭原则。

学生查询"实验"得到 0 条，原因是 R002 已被改为占用状态。学生视图先按状态过滤，再匹配名称。顺序是刻意的：先做权限过滤，再做关键词匹配，不会出现"匹配到了但无权查看"的中间结果，也就不需要额外的权限提示。

## 六、等价性验收

十五组场景，其中十一组为回归、四组为新增查询：

```
管理员搜「会议」    R001，1 条
学生搜「实验」      0 条（占用资源不可见）
学生搜「投影」      R003，1 条
管理员搜「室」      R001 / R002 / R004，3 条
```

其余场景输出与 V2.1 逐字一致，包括错误提示。重构的验收标准即在于此：查询结果不变，仅实现方式改变。

## 七、单元测试

本轮补 23 条用例，全部围绕查询语义：

| 测试类 | 条数 | 覆盖点 |
|---|---|---|
| `ResourceStoreTest` | 13 | `Optional` 命中/未命中/`null` 编号、按状态筛选与升序、名称模糊匹配与首尾空格、空关键词视为不限、组合查询四种条件组合、编号不复用、条件删除 |
| `ResourceManagerTest` | 10 | 学生与管理员搜索范围差异、提示回显关键词与条数、无匹配仍为成功、学生查占用资源失败、空白编号失败、`orElseThrow` 链路、新增后可见、修改后可见性变化、删除 |

其中三条用例专门针对"改造中最易出错的路径"：`findById(null)` 必须返回空 `Optional` 而不是抛异常；`search(null, null)` 必须返回全部；`search(AVAILABLE, "")` 必须只按单一条件筛选。这三条对应 `filter` 中两个"条件为空即不限"的判断，一旦有人改动条件表达式，测试即报差异。

## 八、与课程内容的对应

| 概念 | 落点 |

| 低耦合 | 业务层只传条件，不关心筛选如何实现 |

## 九、旧代码保留

每个方法上方以注释形式保留旧的 `for` 循环。目的不在留念，而在两处实用价值：任务书要求保留写法对比；讲解代码时可直接指出"旧写法五行、新写法三行，省掉的是临时集合的创建与逐条添加"。
